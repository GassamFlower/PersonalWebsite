## 0. 技术栈基线（来自 d-技术选型）

- **Astro**（静态优先）+ 原生 CSS（token）+ Markdown 驱动 + 静态托管。
- 单页站，输出为干净 HTML/CSS/少量 JS。

> **v3（2026-08 用户授权换栈）**：本基线更新为 **Vite + React 18 + r3f（three）+ 经典 CSS（CSS Modules + 全局 token）+ Markdown 驱动**。输出仍为 `vite build` 生成的纯静态 `dist/`（无后端/数据库/登录/接口）。内容/视觉/9 分区不变。新目录结构见 §11。

## 1. 目录结构规则（每个目录职责 / 放什么 / 不放什么）

```
PersonalWebsite/
├── public/               # 静态资源原样输出（图片/图标/favicon）
├── src/
│   ├── content/          # 内容真源（Markdown/数据文件）
│   │   ├── growth/       #   成长记录（.md，月度一更）→ 唯一动态数据
│   │   ├── cases/        #   项目案例（.md，脱敏内容）
│   │   └── config.ts     #   内容 schema 定义（Frontmatter 校验）
│   ├── components/       # Astro 组件（分区/时间线/案例卡/页脚等）
│   ├── layouts/          # 页面布局（Base.astro 统一定：字体/shead/导航/背景）
│   ├── pages/            # 页面（index.astro 单页）
│   └── styles/           # 全局样式 + CSS token（配色/字体/间距变量）
├── src/content.config.ts # 内容集合声明
├── astro.config.mjs      # Astro 配置
├── package.json
└── .gitignore            # node_modules / dist / .env / *.log
```

**职责边界：**
- `content/` = **内容真源**（成长/案例/能力），改内容只改这里，不碰组件。
- `components/` = 展示逻辑，不含业务内容硬编码。
- `styles/` = 设计 token + 全局样式，配色/字体只在这里定义。
- `public/` = 二进制素材（骨白纸/石质噪点可省 + 案例脱敏示意槽，如需）、示意图/截图，不改在 src 里。

**不放**：不放任何"一次性实验文件"、不放未脱敏截图、不放公司/客户信息、不放 node_modules/dist 到版本库。

---

## 2. 接口响应规则

- **本站无后端、无 API 接口**。所有数据在构建时由 Astro 从 `content/` 生成静态 HTML。
- 若未来引入第三方服务（如富文本/统计/表单），遵循"第三方 SDK 官方规范 + 前端调用"，不自定义后端接口。

---

## 3. 错误处理规则

- **无后端运行时错误**。前端少量 JS 需处理：
  - **复制微信号**：`navigator.clipboard` → 失败用 `prompt` 兜底（老浏览器）。
  - **动效降级**：`IntersectionObserver` 不可用或 `prefers-reduced-motion` → **全量显示，不隐藏内容**。
  - **图片懒加载失败**：alt/占位，不破布局。
- 原则：**内容绝不因 JS 失败而不可见**（关键内容在无 JS 时仍完整）。

---

## 4. 日志规则

- **无后端日志**。
- 前端：不记录用户数据（合规）。如需统计，用**隐私友好的第三方**（如不采集 PII），待上线门评估。
- 开发/构建日志：遵循 Astro/构建工具标准输出，不入版本库。

---

## 5. 数据库连接规则

- **本站纯静态、无数据库**。
- 唯一"数据存储" = `src/content/` 下的 md 文件 + 每次构建生成的静态 HTML。
- **不含**连接池/事务/ORM。

---

## 6. 权限入口

- **无登录、无多角色、无鉴权**（立项已明确不做）。
- 唯一的"权限"是**内容维护权限**：由站主本人管理 `src/content/`，通过 Git 版本控制保证可追溯。
- **不含**认证中间件/角色校验/数据归属校验。

---

## 7. 框架复用边界（必须用框架 / 可封装 / 禁止自造）

- **必须用框架**：
  - Astro 的路由/构建/内容集合（不自己写构建器）。
  - 组件的现代化：Astro 组件语法。
- **可封装**：
  - 分区组件（首屏/能力/时间线/案例/联系/页脚）。
  - 设计 token（CSS 变量：配色/字体/间距）全局复用。
  - 内容 schema（content config）校验 md 字段。
- **禁止自造（应用现有能力代替代方案）**：
  - ❌ 不手写 HTML 生成器替代 Astro 构建。
  - ❌ 不引入 React/Vue 做这种极简站（大材小用）。
  - ❌ 不自定义 CSS 框架（用 token + 原生）。
  - ❌ 不留任何"一次性问题修复脚本"在 src 里。
- **唯一例外（2026-08 用户授权）**：引入 `three`（WebGL）做**高光点 3D 粒子**，因原生 CSS 无法实现真实 WebGL 场景——这是「应用成熟库而非自造」的正确用例。**仅限定高光位置 + 克制度**，不因此放开"React/Vue 全家桶"禁令；依赖清单见 `docs/d-技术选型.md` §5.5。

---

## 8. 架构小结

- 纯静态 Astro 站：**内容真源沉淀在 `content/`，展示在 `components/`，样式统一走 token**。
- 架构规则以"**内容可维护、匿名可追溯、无 JS 也可用**"为核心。
- 这 7 项适配最重要的意义：**定死"内容/展示/样式"的三分离，以及"绝不引入不必要复杂度"**——它让个人站既可长期维护、又符合诚实/匿名红线。

## 11. v3 目录结构与框架复用（用户授权换栈后更新）

> 本节为 v3（Vite + React + r3f）专属；与上方 V1 Astro 结构冲突处以后者为准。

```
src/
├── content/                 # 内容真源（md, 原样保留）
├── assets/styles/global.css # 设计 token（:root 变量，v4 原值平移）
├── main.tsx                 # React 挂载入口
├── App.tsx                  # 组装 9 区
├── lib/                     # md → 结构化 JS 的解析工具（构建时读入）
└── components/
    ├── Hero/                # 含 r3f 3D 背景（唯一 3D 位置）
    ├── Story/ Timeline/ Cases/ CapabilityMap/
    ├── Growth/ Principles/ Contact/ SiteNav/ Footer/
    └── ui/                  # .section-head / CTA / 徽章 复用件
```

**框架复用边界（v3）**：
- 用 **React 组件**而非自造 HTML 生成器；用 **Vite 构建**而非手写打包。
- r3f 仅 Hero 一处背景；**不引** react-router（单页锚点原生）/ zustand 全局状态 / GSAP 动效全家桶。
- 内容 / 展示 / 样式三分离沿用；组件不硬编码业务文案。
- 动效纪律：`prefers-reduced-motion` 时 r3f 不挂载、内容全显；无 JS 时关键内容可见。
- 好代码资产（粒子 / Hero 交互）尽量由原 `.astro` 脚本平移动画 r3f，不改行为。

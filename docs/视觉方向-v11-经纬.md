## 0 诊断（实测）

### 0.1 观感缺口

当前首屏是黑底、白字、白档案卡的三层平面：信息清楚，气质成立，但空间记忆只有排版与发线。首屏没有可感知的深度、材质或运动，访客记住的是「一份文档」，留不下「一个物体」的印象。读代码可确认：

- `site-react/src/components/Hero/Hero.tsx:1` 注明「3D 粒子已按 Q3=b 移除」，`site-react/package.json` 无 `three`，全站无 3D。
- `site-react/src/styles/global.css:14-36` 的三色体系（米白 `#f7f4ef`、墨黑 `#1a1a1a`、砖红 `#bc4832`）与两套字体（衬线标题 + IBM Plex Mono 事实行）是既有强资产，不应推翻。
- 手绘批注、裁切线、竖排书口、深墨色带、档案卡是站点的识别符号，应继续使用。

### 0.2 机器可读层缺陷（安全、可复现）

| 缺陷 | 证据 | 对搜索与 AI 抓取的影响 |
|---|---|---|
| `robots.txt` 仍指向旧域名 | `site-react/public/robots.txt:3` 写 `https://gassamflower.github.io/PersonalWebsite/sitemap.xml` | 爬虫按 robots 找到的站点地图属于旧地址，与当前 `https://onetale.cn/` 不一致 |
| `sitemap.xml` 仍指向旧域名，且缺文章页 | `site-react/public/sitemap.xml` 只有 2 条 URL，全部是 `gassamflower.github.io/PersonalWebsite/`；没有 `/writing/four-gates/` 与 `/en/writing/four-gates/` | 文章页不在站点地图内；旧域名条目可能把抓取引向重定向地址 |
| 站点地图靠手写静态文件 | 同上；构建脚本 `site-react/scripts/prerender.mjs` 只发射 HTML，不生成 sitemap | 每次新增文章都要手工改文件，迟早再次出现过期 |
| 无 RSS/Atom | `site-react/public/` 目录无 feed 文件；head 无 `rel="alternate" type="application/rss+xml"` | 聚合器与部分 AI 检索侧没有低成本订阅入口 |
| 结构化数据只覆盖两层 | `site-react/index.html:29-60` 只有 `Person` + `WebSite`；`prerender.mjs:87-102` 每篇文章一条 `BlogPosting` | 缺 `ProfilePage`、`BreadcrumbList`、案例清单；文章的 `image`、`publisher` 字段不完整 |
| AI 爬虫策略靠通配符隐含 | `robots.txt` 只有 `User-agent: *` | 检索类与训练类爬虫没有明确许可，第三方审计时无法一眼确认意图 |
| `llms.txt` 被当成万能文件 | `docs/q-SEO-GEO出海服务线-立项建议.md` §1.4 记录 5.15 亿次请求里几乎无人读取；83 个站 12 周仅 7 次 | 本次不创建 `llms.txt`；把精力放在可抓取 HTML、robots、sitemap、结构化数据与 feed |

结论：搜索与 AI 抓取的问题不在「页面写得好不好」，而在机器层有三处过期或缺失。修法应当是构建期生成，避免再次漂移。

## 1 方向（唯一推荐）

**经纬：把首页从「黑色封面」改成「纸面工作台」，让一团墨线在纸面上组装成可用的结构。**

首屏改为米白纸面。右半部用 three.js 绘制一组极细的墨线：起始是缠绕的乱麻，1.8 秒内收束成等距结构框；其中一根砖红线穿出结构，末端留在纸面，保持松散。左边的巨衬线标题、右下的档案卡、裁切线、色标与手绘圈注全部保留。档案卡由「压在黑场上的白卡」改成「叠在纸面上的两张底纸 + 一张卡面」，用 1px 墨线与错位底纸做出厚度，不用大阴影。

选择这一条的理由：

1. **主张可视化**。站点的主张是「把一团乱麻，理成能用的系统」。乱麻收束成结构，正是这句话的形状；观众先看到动作，再读到句子。
2. **识别符号延续**。纸、墨、砖红、档案卡、裁切线全部来自 v6–v9 的既有体系；换的是空间与材质，身份的连续性不丢。
3. **避开常见做法**。深色背景加发光粒子是所有 3D 作品集的默认解；纸面墨线更像建筑事务所的模型台，记忆点来自材质与留白。
4. **诚实可解释**。那根没有收进结构的砖红线，对应案例卡里真实存在的边界与未完成项；装饰本身也守诚实。

明确不做：

- 不改三色 token，不改两套字体，不改 9 分区，不改内容真源。
- 3D 只出现在 Hero 一处；故事区、案例区、封底不挂 3D 画布。
- 不做滚动劫持、不做鼠标跟随光圈、不做发光、不做玻璃拟态、不做渐变大背景。
- 不新增圆角卡片、阴影堆叠、彩色标签。
- 不创建 `llms.txt`，理由见 §0.2。

## 2 Hero 3D 规格

### 2.1 场景

| 项 | 规格 |
|---|---|
| 依赖 | `three`（原生 API），不引入 `@react-three/fiber`。场景只有一个画布、一组线、一次进场动画，用 React 管理 3D 状态没有收益；原生 three 让 chunk 更小，SSR 边界更清楚 |
| 加载 | 动态 `import('three')`，在首屏水合完成后的空闲时段加载；加载完成前显示静态 SVG 线稿，加载失败保持静态线稿 |
| 几何 | 桌面 896 条线段（16 段/长线），移动端 448 条（8 段/长线）；每条线段两个端点，起始位置来自固定种子的伪随机缠绕，终点落在等距结构框的边与内部网格上 |
| 材质 | `LineBasicMaterial`，`transparent: true`，`depthWrite: false`；墨线 `#1a1a1a` 进场 0.18→0.50，朱线 `#bc4832` 进场 0.28→0.75 |
| 动画 | 插值进度 0→1，时长 1.8s，缓动 `easeOutExpo`；端点逐帧插值（CPU 写 position，不进 React 状态）；进场结束后仅保留极慢自转（±0.09 rad）与指针视差（最大 ±0.06 rad） |
| 滚动 | Hero 在视口内时，滚动进度只影响画布组的轻微旋转（最大 ±0.08 rad）；不改变页面滚动行为 |
| 画布尺寸 | 绝对定位在 Hero 右半部，宽 58%，高 100%；`pointer-events: none`；左缘用 `mask-image` 渐隐，避免压住标题 |
| 渲染 | `antialias: true`，`alpha: true`；桌面 DPR 上限 1.5，移动端 1.2；无阴影、无后期处理、无贴图 |
| 帧率 | 桌面连续渲染；移动端上限 30fps；页面隐藏或画布离开视口时暂停 |
| 预算 | three chunk gzip ≤ 190KB；首屏初始 JS 体积不增加；LCP 仍是预渲染文本，画布不参与 LCP |

### 2.2 降级与无障碍

| 条件 | 行为 |
|---|---|
| 无 JS / JS 失败 | SSR 输出静态 SVG 结构线稿；文案、档案卡、链接完整可读 |
| `prefers-reduced-motion: reduce` | 不加载 three；静态 SVG 显示「收束完成」状态 |
| WebGL 不可用 | 不创建画布；静态 SVG 保留 |
| 移动端 | 不监听指针视差；线段减半；30fps 上限 |
| 键盘 | 画布 `aria-hidden="true"`、不进入 Tab 顺序；全部交互仍在原生 `<a>` 上 |
| 内存 | 组件卸载时释放几何、材质、渲染器与事件监听 |

### 2.3 静态后备图

静态 SVG 由 Hero 组件内联输出，使用与 3D 同一套等距结构线坐标（构建期生成固定路径），不请求额外图片。它同时承担三件事：无 JS 时的视觉、reduced-motion 时的终态、three 加载失败时的兜底。

- 底色由 `--color-field` 改为 `--color-base`（米白）；Hero 内文字改为墨色系；裁切线与色标改为墨色。

### 3.2 全站

- 故事区插画加一层 24px 的滚动视差（CSS transform + IntersectionObserver），`prefers-reduced-motion` 时关闭。
- 案例线稿、手绘批注、竖排书口、规格表全部保留。
- 不新增颜色、组件或分区。

### 3.3 文案

- 首屏文案不改。若标题在纸面上显得过重，只调整字号与行高，不改字句。

### 4.1 抓取层

**robots.txt 改为构建期生成**，内容包含：

```

Allow: /

Allow: /

Allow: /
User-agent: Claude-User
Allow: /
User-agent: Claude-SearchBot
Allow: /
User-agent: Bingbot
Allow: /
User-agent: Googlebot
Allow: /

# 训练类（站主裁决，推荐放行）
User-agent: GPTBot
Allow: /
User-agent: Google-Extended
Allow: /
User-agent: ClaudeBot
Allow: /

Allow: /
User-agent: Applebot-Extended
Allow: /
User-agent: meta-externalagent
Allow: /

Sitemap: https://onetale.cn/sitemap.xml
```

说明两条容易误解的规则：

- `Google-Extended` 控制的是训练与部分生成式能力，不影响 Google 搜索与 AI Overviews；AI Overviews 走 `Googlebot`。
- `llms.txt` 不创建；它的读取率证据见 §0.2。

**sitemap.xml 改为构建期生成**，数据源与 `prerender.mjs` 的页面清单同源：

- 4 条 URL：`/`、`/en/`、`/writing/<slug>/`、`/en/writing/<slug>/`。
- 每条带 `xhtml:link` 双语互指与 `x-default`（主页）。
- 文章条目不写 `lastmod`：真源 `date` 只到年月（`YYYY-MM`），补日会制造假精度；`priority` 与 `changefreq` 同样不写。
- 新增文章只改内容真源，站点地图随构建自动更新。

**RSS 2.0**：

- 生成 `/rss.xml` 与 `/en/rss.xml`，每条包含 `title`、`link`、`description`、`guid`；`pubDate` 因真源只有年月而不写，不编日期。
- 两个主页 head 增加 `<link rel="alternate" type="application/rss+xml" href="...">`。
- 不做全站聚合 feed，避免中英文条目混在一条时间线里。

### 4.2 结构化数据

| 页面 | 类型 | 字段（只写站内已成立的事实） |
|---|---|---|
| 主页 | `ProfilePage` | `mainEntity` 指向 `Person#person` |
| 主页 | `Person` | `name`、`alternateName`、`jobTitle`、`url`、`image`（`avatar.png`）、`sameAs`（仅 GitHub）、`knowsLanguage`、`knowsAbout` |
| 主页 | `WebSite` | `url`、`name`、`inLanguage`、`publisher` |
| 主页 | `ItemList` | 3 张详案卡：`ListItem` → `CreativeWork`（`name`、`description`、`url` 指向 `#case-N`）；不写评分、价格、客户名 |
| 文章页 | `BlogPosting` | 现有字段 + `image`（站点分享图）、`publisher`、`articleSection`；`datePublished` 取真源，`dateModified` 无据不写 |
| 文章页 | `BreadcrumbList` | 首页 → 写作 → 本篇（两个语言各自的路径） |

所有 JSON-LD 在构建期用 `JSON.parse` 校验，字段缺失即构建失败；上线后再用浏览器与结构化数据校验工具复核。

### 4.3 度量

- 构建断言：sitemap 4 条 URL、robots 含 `onetale.cn` 与 AI 组、两套 feed 可解析、每页 JSON-LD 可解析。
- 线上断言：`curl -I` 检查 `/`、`/en/`、`/writing/four-gates/`、`/sitemap.xml`、`/robots.txt`、`/rss.xml` 均 200；正文 HTML 含关键事实句。
- 站主操作：Google Search Console 与 Bing Webmaster Tools 提交 sitemap；30 天后看抓取与索引数据。本站无法承诺排名或 AI 引用次数。

### 4.4 诚实边界

- 结构化数据与可抓取 HTML 能提高被理解与被引用的概率，无法保证出现在 AI 答案里。
- 站外语料层（社区、清单页、评价站）不在本次范围；`docs/q` 已说明这层是人力密集的独立工作。
- 本次不提交任何假评价、假评分、假价格、假客户。

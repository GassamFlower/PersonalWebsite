## 2. 方向对比（带排序）

| 序 | 方向 | 加什么 | 收益 | 成本 / 风险 | 裁决 |
|---|---|---|---|---|---|
| 1 | **A · 节点与流（推荐）** | 6–10 个交点节点 + 一道朱线脉冲 | 线稿从「线」读成「经纬」；朱线成为路径而非装饰 | ~40 行，0 新依赖；无节点时不影响降级 | **推荐** |
| 2 | B · 纵深 | 远段降低不透明度 + 随滚动轻微推拉相机 | 更「空间」，更接近剖开的骨架 | 需逐顶点配色；推拉与滚动倾角可能打架；削弱印刷感 | 备选 |
| 3 | C · 指针联动 | 指针邻近的节点提亮 / 悬停档案卡点亮节点 | 交互感强 | 移动端无指针；三张精选卡与任意节点的映射是虚构语义，违背诚实红线 | **不做** |

## 3. 推荐方案 A 的具体规格

1. **节点**：取两端框架的四个角（`±0.95, ±0.72, z=±1.05`）共 8 个交点，`THREE.Points`，墨色；收束完成后 400ms 淡入（不参与收束位移，避免漂浮）。**实测微调**：2px / `opacity 0.35` 比收束后的线（0.5）还浅，落到角上与线端混在一起看不出来，故提到 **2.5px / 0.55**——节点必须略重于线才读得出是交点。
2. **朱线脉冲**：沿既有朱线折线每 **10s** 走一次，长度约路径 6%，线性推进、首尾各 8% 淡入淡出。**实测微调**：同为朱色的 1px 线叠 2px 点仍不够醒目，改为 **2.5px 点、`opacity 0.9`**（线是 0.75 的淡朱，点更实），读作一粒沿朱线游走的光点。
3. **移动端**：节点减到 4 个（仅正面），脉冲周期放慢到 14s、采样点 12→8；沿用手势不监听、30fps 上限。
4. **性能预算**：新增 2 个 `Points` + 每帧 1 次小数组更新（桌面 12 点 / 移动 8 点）；不新增 chunk、不新增依赖；桌面 60fps、移动端 30fps 不退化。
5. **降级**：reduced-motion / 无 JS / WebGL 失败时仍只有静态 SVG，节点与脉冲都不存在（静态 SVG 构图与 v11 一致）。

## 4. 明确不做

- 不做 bloom / 后处理 / 景深：纸面印刷语言不需要发光。
- 不做滚动劫持、相机推拉、鼠标聚光、粒子雨。
- 不给节点贴 `HOST / DB / GATE` 标签：3D 里没有真实系统映射，贴标签就是编事实，也会和右侧档案卡抢信息。

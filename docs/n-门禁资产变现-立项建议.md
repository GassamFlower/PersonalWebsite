## 0. 这份文档解决什么问题（先给结论）

用户在问「国外都在做智能体助手，我该如何依附它们赚钱」。

**唯一推荐：不做智能体产品，做「智能体交付的门禁」——把本仓已经跑通的验收/反夸大机制做成可安装的资产包，靠内容与服务变现，不靠平台分成。**

依据三条，全部可核：

1. **智能体平台位已被占死，且个人投不进去。** 国内外均已量产（§2 事实卡 A/B），国内 C 端个人通道 2026 年反而在收窄。
2. **用户当前档位不能卖 AI 能力。** `src/content/skills/ai.md` level 为「会用」，`src/content/offcat/a-03-agent.md` status 为「计划中」（原文：还没到"会用得很稳"）。卖 agent 解决方案直接违反宪法 §7。
3. **唯一已被实物验证过的、别人抄不走的资产，恰好是 2026 年最缺的那一层。** 本仓 `scripts/check-content.mjs`（251 行，已入库、build 末尾真跑、失败 `exit 1`）里有 7 族断言，其中 `:172-177` 把「能力档位只允许 已交付/会用 两档，出现第三档或"精通"一律拦停」写成了代码。智能体现在能替人动手，但**没人能给它的产出做验收**——这就是缺口。

## 3. 立项说明（是什么 / 面向谁 / 解决什么）

### 是什么
**「AI 交付验收包」**：一小套可安装的门禁资产——`SKILL.md`（告诉 coding agent 每次交付前必须做什么）+ 一个可直接跑的验收脚本（本仓 E1 的通用化版本）+ 一份过门标准模板。作用对象是**用 AI 产出东西的人**：他们能生成，但不能证明生成物可用。

### 面向谁（三类，按付费确定性排序）
| 受众 | 痛点 | 我给的东西 | 付费形式 |
|---|---|---|---|
| 用 AI 交付的企业/团队（B 端） | 不敢信 AI 产出的质量与边界，出事无人担责 | 内部交付门禁落地 + 验收台账模板 | **定制接单**（主收入） |
| 独立开发者 / AI 编程用户 | 提示词技能泛滥，没人管结果对不对 | 免费门禁样例（英文）＋ 完整版换邮箱 | 漏斗，养品牌 |
| 同行 / 学习者 | 想知道"怎么让 AI 交付可信" | 方法论短文库（本仓 i/j/k/m 已建立的写作机制） | 内容/咨询 |

### 解决什么问题
对站主：把「会做但没有可下单 SKU」这一具体缺口补上，且**不需要**自称精通 AI——卖的是「我有一套验收规矩，且已写成会拦停的代码」。

### 核心价值主张（一句话）
> AI 能替你动手，但不能替你负责。**我把"负责"做成了构建期会拦停的门禁。**

## 4. 功能边界（做什么 / 绝不做什么）

### 做（v1 有且仅有三件）
1. **一份真实可用的门禁样例**：把 E1/E2 抽成通用版，放进独立 GitHub 仓库（站外），含 `SKILL.md` + 断言脚本 + 过门标准模板。
2. **站内一个静态子页/条目**：留档说明「这套门禁拦住过什么」——只写本仓 git 历史里可指出的真实拦停，无可指则写"当前无拦停记录"。
3. **一组方法论短文**（走 `docs/j-写作流程.md` 既有流程 + `外站-X-内容日历.md`）：主题为 AI 交付验收，英文发 X、中文引流。

### 不做（划界，含理由）
- ❌ **不做智能体产品/平台/聊天入口**——§2 A/B，位已被占，个人无算力与流量。
- ❌ **不宣称 AI Agent 开发能力**——`skills/ai.md` 档位为「会用」，宪法 §7 禁止上抬。
- ❌ **不做在线报价 / 服务清单页 / 价格页**——沿用 `docs/a-立项文档.md:46` 原决议，**本建议不申请豁免**。价格只在私聊谈。
- ❌ **不为变现引入后端/数据库/登录**——宪法 §1 不放宽；线索采集沿用 v0.2 §32 已授权的第三方静态表单。
- ❌ **不虚构客户、案例、量级数字**——宪法 §4/§5/§8。无人付费则写"尚无付费客户"，此项必须与真实台账一致。
- ❌ **不做付费模板/收费插件上架**——§2 C，个人不具受邀资格。
- ❌ **不动 9 分区既有内容与视觉基线**——宪法 §11/§30，新增须先改 `docs/a-立项文档.md`。

## 5. 门禁依赖（本文不能自己给自己开门）

本建议若要推进，**必须按序过门，且第 ① 项是硬前置**：

1. **立项门（用户裁决）**：`docs/a-立项文档.md` 需新增决议——是否允许「资产留档页」这一内容单元（依 §11 精神 + v0.2 §33 须先改立项文档并经用户确认）。**未确认则本建议止步于此，不进架构门。**
2. **架构门**：门禁资产包的技术选型（是否含 MCP，是否只做 SKILL.md+脚本）、目录结构、与 `check-content.mjs` 的共源关系（禁止平行事实源）。
3. **业务门**：过门标准模板与拦停证据的真实材料（含匿名化/脱敏复核）。
4. **上线门**：外部仓库可达 URL + 站内留档页真机截图 + 一次真实拦停记录。

> 成本纪律（宪法 §18-21）：本建议 v1 全部工作量为**一份脚本通用化 + 一页留档 + 4 篇短文**，不开新项目目录，不进 node_modules/dist/.git 检索。

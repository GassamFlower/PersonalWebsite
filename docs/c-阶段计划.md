# c · 阶段计划 · Personal Website

> 项目：Personal Website（个人网站 · 接单交付凭证）
> 门禁：立项门 · 阶段 1·立项
> 上游：`docs/a-立项文档.md` + `docs/b-功能清单.md`
> 状态：`[草稿]`，待用户确认
> 原则：第一阶段 = MVP（能跑通**接单转化闭环**的最小可用版本）；后续阶段基于用户实际迭代，不细化到技术实现。

---

## 一、阶段总览

| 阶段 | 名称 | 包含功能 | 目的 | 交付物 |
|---|---|---|---|---|
| **P1** | **MVP · 接单闭环版**（第一阶段） | 首屏 / 四梯队能力地图 / 做过的事 / 项目案例 / 联系交流 + 底部 + 导航 | 跑通"访客→了解→判断→联系"核心闭环，可上线接单 | 可访问的单页站（结构完整、核心转化先通）|
| P2 | 内容增强版 | 品牌故事 / 成长记录 / 做事的规矩 | 增信任、显自驱、看体系 | 补齐另 3 个分区，信任更厚 |
| P3 | 打磨与上线 | 案例截图补齐 / 文案打磨 / 部署 | 高质量上线 | 脱敏截图就位、部署可达 |
| P4（远期） | 迭代反哺 | 成长月度更新、案例增补、Skill 反哺 | 长期维护 | 每月更新记录 |

---

## 二、为什么这么排（对齐 MVP 原则）

- **P1 优先打通「接单转化」**：把最能促成"加微信"的四个东西（定位/能力/证据/联系）先做出来，让站**尽快能接单**。这是 MVP 的"核心流程"——需求方看到→判断→联系。
- 品牌故事/成长/规矩是**加分项**，不影响"能不能联系上"，放 P2 补齐，避免 MVP 拖长上线。
- **内容优先于代码**：P1 就保证"结构完整、内容用真实素材"，不让结构残缺阻塞上线。
- 每个阶段都能独立验收，不依赖技术实现细节（选型在架构门定）。

---

## 三、Phase 边界与验收

### P1 · MVP · 接单闭环版
**包含功能**：① 首屏 ② 四梯队能力 ③ 做过的事 ④ 项目案例（文字+占位示意）⑤ 联系 ⑥ 底部 + 全局导航。
**不做（本阶段）**：品牌故事、成长记录内容、做事的规矩（占位不显示）、不追求截图精美。
**验收**：9 分区结构对应（未做分区占位/不显示）；核心 4 区可用；桌面/移动可访问；"加微信"可用；匿名化合规。

### P2 · 内容增强版
**包含功能**：② 品牌故事 ⑥ 成长记录 ⑦ 做事的规矩 全量内容。
**验收**：9 分区全部有真实内容；成长记录 md 驱动新增一条即出。

### P3 · 打磨与上线
**包含功能**：案例脱敏截图/示意补齐、文案打磨、静态托管部署。
**验收**：可访问 URL；首页与各分区可达；保真台账。

### P4 · 迭代反哺（远期）
**包含功能**：月度成长更新、案例增补、把建站经验反哺知识库。
**验收**：可维护、可演进。

## 五、第二版（P5）· 售后与深化（2026-08 立项决议）

> V1（P1–P4）目标是把「接单闭环」跑通；第二版在其上补售后完备与信任深化，V1 阶段仍有效。

| 子项 | 包含功能 | 目的 | 边界 |
|---|---|---|---|
| P5-1 售后与客服 | 留言表单（第三方→邮箱）+ 客服微信悬浮入口（售前/售后话术）+ 响应承诺「1 工作日内回复」 | 下班不丢客、补全「敢托付」闭环 | 不建自建后台；敏感信息不入站内存储 |
| P5-2 合作流程透明化 | 「询价→开工→验收→售后」四步，并入『做事的规矩』区 | 减需求方焦虑 | 文案可基于四门禁扩展 |
| P5-3 项目过程透明展示 | 案例深化「问题→做了什么→证据→过程留痕」 | 强化交付凭证 | 不造假过程 |
| P5-4 成长内容资产化 | 成长记录升级为方法论短文 | 长期主义 / 内容资产 | 仍 md 驱动，不开博客 |
| P5-5 客户见证（依赖材料） | 脱敏实名甲方反馈 | 增信 | `[来源待补]`：需可脱敏素材，不到位不开 |
| P5-6 克制动效 | 吸顶导航 / 滚动渐进显现 / 微交互 | 交互打磨 | 原生轻量 JS，尊重 prefers-reduced-motion，无 JS 全显 |

**验收**：留言表单可用且漏单自测通过；客服微信入口移动端常驻；合作流程 / 案例深化 / 成长资产化内容到位；响应承诺兑现；纯静态、无后端约束保持。

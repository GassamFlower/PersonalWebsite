## 0. 一句话气质

> 全站只使用**纸白、墨黑、朱砂**三种颜色：你日常产出的就是规格表与工程图纸，那么本站就做成一本**「个人技术图鉴」**——黑头（封面）· 白身（图版 01–08）· 黑腰（核心卷 Cases）· 黑尾（封底），朱砂是全书唯一的红，只出现在盖过章的事实上。

## 1. 三色体系（Q1 已确认）

| 角色 | token | 值 | v6 职责 |
|---|---|---|---|
| 纸白 | `--color-base` | `#F6F6F4` | 正文底、图版纸面（不变） |
| 墨黑 | `--color-ink` | `#1A1A17` | **从文字色升为结构色**：封面/核心卷/封底场域、大编号、全部细线、主按钮反白 |
| 朱砂 | `--color-seal` | `#C43C2B` | **全站唯一彩色**。验收章（v5 纪律原样继承：仅已验证、每屏≤1、全页≤6）+ 封底署名章（新增，见 §5） |
| 朱砂·暗底提亮 | `--color-seal-on-dark` | `#E0705A` | 深墨场内的章（对比度 ≥4.5:1，v5 已落地） |
| 冷灰/浅灰 | `--color-line/faint` | 不变 | **只作线，不作小字**（纸白上 3.16:1 / 1.55:1，不足 AA 文字） |
| 弱文字墨 | `--color-ink-soft` | `#636360` | 铺开时新增：纸白场上的说明/mono 弱文字专用（实测 5.57:1）；仍属"墨的减淡"，不引入第四色相 |
| 墨蓝 | `--color-accent` | **退役** | 见下行过渡策略 |

**退役过渡策略（防漏改纪律）**：`--color-accent` 变量保留但**改指向 `--color-ink`**。任何漏改的墨蓝用法会静默降级为黑（安全），**绝不**降级为朱砂（防破坏"唯一色+≤6 枚"纪律）。全部组件清完显式引用后，下一版删除该别名。

**私有签名装置——三色标**：参考印张套准色标，色序为 墨黑·朱砂·纸白 三格 + 套准圆圈，出现在封面右上与封底，是本站的"色卡署名"。

## 2. 脊柱与色域规则（D 语言）

- 深墨场统一用 `--color-ink`（原 `#17171b` 面板色并入，全站黑只有一种黑）。
- 色带**硬切**：深墨区与纸白区之间无渐变、无过渡带，边界即裁口。
- 节奏：**黑头（Hero）→ 白身（01–08 图版）→ 黑腰（Cases）→ 黑尾（Contact+Footer）**。
- 深墨场内文字=纸白、细线=灰阶提亮值、章=`--color-seal-on-dark`；纸白区反之。

## 3. 图版系统（C 语言 · 全站骨架）

每个分区 = 一张「图版」，统一四件套：

1. **图版眉栏**：`0N · 区名` + mono 行 `CAT.2026-10 · REV v6 · 状态`（v5 批注轨吸收进此栏，`GATE✓` 仅绑真实门禁事实）。
2. **左缘竖排区名**（Q2 已确认）：`writing-mode: vertical-rl`，mono 小字灰色，桌面端（≥1200px）显示，移动端隐藏。线装书口语言，是 v6 的第二记忆点。
3. **规格表体裁**：内容卡统一为 `label │ value │ 发线` 行式表。**字段缺失即不渲染该行**——不编造数据，诚实红线零风险。现有真源字段（status/stack/outcome/evidence/year/role/month）天然适配此体裁。
4. **字阶放开**：封面启用 `--text-hero`（clamp 3.2→5.2rem，v4 定义但从未使用——v6 修正此锁死）；图版大标题 `--text-4xl`；编号 `--text-5xl` 级；正文维持 v4 收敛档。

## 12. 上线门前整改：让「目测通过」能迁移到访客机器（2026-10-14 用户「开始推进」，只做 1/3/4）

v6 的验收一直靠本机浏览器目测，而本机恰好装了这些字体、且 localhost 永远可达——**"我这边好看"里有一部分是访客拿不到的**。本轮把三件不引入新视觉决策、却决定观感能否迁移的事做完。

### 12.1 衬线自托管（可达性）

| 事实 | 数据 |
|---|---|
| `fonts.googleapis.com` 在大陆网络 | 本机 curl 12s 超时 → 访客此前实际渲染的是系统回退字，§5 衬线字阶在别人机器上不成立 |
| 全量 Noto Serif SC | 3.1 MB / 字重，101 个 unicode-range 分片；整页文本命中 21 片 = **806 kB / 字重** → 分片方案不可用 |
| 子集化方案 | `scripts/fonts.mjs`：`fontTools.varLib.instancer` 固化字重 → `fontTools.subset` 按实际渲染字符裁字（fontTools 4.60 的 subset 无 `--instancer`，故分两步） |
| 结果 | 810 码位 / 字重约 122 kB；`assets/fonts/*.woff2` 入仓（CI 机器上没有源字体，产物必须提交） |
| 守卫 | `build` 末尾挂 `node scripts/fonts.mjs --check`：拿 `dist/index.html`（两条线）+ `src/content/**/*.md` 的渲染字符与 `assets/fonts/serif-coverage.json` 比对，缺字即 build 失败。本轮它已抓到 2 次（新增的「跳到正文」「哪」） |
| 拉丁等宽 | IBM Plex Mono 无中文、整字重仅 15 kB，直接从 `@fontsource` 产物复制入库（400/500） |

### 12.2 分享卡片（第一次见面的脸）

- `scripts/og_image.py`（`npm run og`）用 Pillow 按 v6 语言绘制 1200×630：纸白底 + 墨黑细线 + 裁切线 + 三色标 + **一枚朱砂署名章**。**不用 AI 生图**——生图会产出笔画糊掉的假汉字，直接踩诚实红线。
- 一次写出两条线的静态根：`public/og.png` 与 `site-react/public/og.png`。
- **踩坑记录**：`.gitignore` 里的 `images/` 本意是挡生图草稿，但它同时挡住了 `public/images/`，卡片放进去就等于没部署（CI 检出后站点无此图）。故落 `public/og.png`。
- meta：`og:type/locale/site_name/url/title/description/image(+width/height/alt)` + `twitter:card=summary_large_image`（title/description/image 由 OG 同名标签兜底，不重复写第二遍）；`og:image` 必须是绝对 URL（微信/钉钉不解析相对路径），基址取 `astro.config.mjs` 的 `site`。两条线的 head 各一份。

### 12.3 无障碍三件（不改视觉）

## 1. 两条边界（先划死，避免走回头路）

### 1.1 不做独立文章页（本批）

宪法 §1 是纯静态**单页**站，§1.1 只放开「两个静态 HTML = 一种内容的两种语言」。多页 = 修宪，须用户显式批准，不在本批范围。

采用**原生 `<details>/<summary>` 就地展开**：

- 正文在初始 HTML 里，**无 JS 也读得到全文**（§17 比折叠前更强，不是更弱）。
- 零依赖、零自造框架、键盘可达（`Tab` 到 `summary`，`Enter` 展开）。
- 分享定位用锚点 `#writing-<n>`，够 `docs/外站-X-内容日历.md` 用。

**触发下一次立项的条件（写死，防止无限拖延）**：文章 ≥ 6 篇，或 zh 初始 HTML > 200 kB。届时再开「文章页静态副本」批并讨论修宪。

### 1.2 不复活已被 v7 撤下的装置

`技术栈 rail`、`labelStack`、雷达图 / 能力图谱（CapabilityMap）均已整区下线，**本批不得以"加 skill"为由请回任何一种**。理由沿用 v7 的裁决：那些是自我表功式装饰，且用户明确反感。

能力档位的体裁 = **台账条**（沿用附录 A-0n 胜出的版式语言：标签行 > 竖线缩进列 > 行间发线），一行一个域，只说三件事：**域、档位、一句话边界**。档位只有两档可用（`已交付` / `会用`）——**skills 真源里没有「在学」档，就不画「在学」**，代编即踩诚实红线。

## 2. 区序与编号（唯一推荐，不是选项菜单）

新区「能力档位」插在**案例 03 之后**，编号 04；后续全部顺延。

```
封面 → 02 故事 → 03 案例 → 04 能力档位（新） → 05 写作 → 06 来路 → 07 成长 → 08 规矩 → 附录 → 09 封底
```

为什么紧挨案例：案例回答「做成过什么」，档位回答「手上的工具到什么程度」，读者这两问是连着的；放来路/成长之后就近了叙事尾巴，说服力衰减。

改动面（落码时逐条核对）：`App.tsx` 插组件；`SiteNav` 标签与编号；5 个组件里硬编码的 `plateRail` / `<span className="meta">0n</span>`；`i18n/ui.ts` zh+en 双份；`Contact`/`Hero` 三链目标不变。

## 3. md 契约（写作 v2）

```yaml
---
title: 中文衬线字体，我裁到 122 kB
date: "2026-10"
summary: 一句话摘要（列表行显示）
titleEn: "..."
summaryEn: "..."
---
正文用 markdown body（段落空行分隔）。
```

- **正文放 md body，不放 frontmatter**：`body` 已被 growth 集合占为字段名（`GrowthData.body`），复用键名会让 `hasAll` 判别与守卫语义打结。`getWriting()` 改为携带 `Entry.body`。
- 判别键仍是 `title+date+summary`（`content.ts:82`），加 body 不影响判别。
- `published: false` 可压稿（沿用 cases 的既有做法）。
- 正文内**禁止**：外链图片、真实公司/客户名、无法回原文核对的数字、代码仓库里不存在的路径。

## 4. 守卫（三处，缺一即视为未落地）

1. `scripts/check-content.mjs` 新规则④：writing 集合每篇须有 `titleEn` + `summaryEn` + `bodyEn`；**body 与 bodyEn 都非空**才允许入列表；缺键 `exit 1`（沿用 i18n 批 2–4 的纯拉丁串豁免）。
2. `node scripts/fonts.mjs`：文章正文必然带入千位新字 → 改完内容**必须**重跑再 build，否则 `--check` 报红（历史上「跳」「哪」「曾」三次实测拦停）。子集体积涨幅须记录在本文 §7。
3. 展开态可访问性：`summary` 必须有可见 `:focus` 环（本环境验聚焦态须发真实 `Tab` 键，`element.focus()` 会误判）。

## 5. 机器可读层承接

`site-react/index.html` 的 JSON-LD `@graph` 已有 `Person` + `WebSite`。本批追加：每篇一个 `BlogPosting`（`@id` = `#writing-<n>`、`inLanguage`、`datePublished`、`author` 指 `#person`、`isPartOf` 指 `#website`）。
**顺带修一处口径冲突**：批 4 写的 `knowsAbout` 是一份技术栈清单，而 v7 已把技术栈展示整面下线；改为按 skills 真源的**域 + 档位**语义（「数据采集与自动化」「运维与部署」等），不列具体框架名。

## 6. 内容要你自报（我不代笔，这是红线不是托词）

`docs/j-写作流程.md` §1：文章必须是本人经历与观点，AI 只做结构、标点、双语对照。落地节奏 = **你口述 raw → 我整理结构与 `*En` → 你逐条裁决 → 落盘**。

第一篇推荐：**《中文衬线字体，我裁到 122 kB》**。选它的理由是风险最低而非最炫：素材（`scripts/fonts.mjs`、806 kB vs 122 kB 的实测、Google Fonts 在大陆 curl 12s 超时、两次守卫报红）**全部已在本仓库里可核对**，不涉及任何客户与脱敏，且你只需回答事实与取舍，不需要回忆现场细节。

需要你口述的六问（答完我就能出结构与双语）：

1. 为什么不用系统字体兜底 / 不用 `font-display: swap` 蒙过去？
2. 806 kB 这个数当时怎么算出来的，看到它时决定怎么办？
3. `fontTools instancer + subset` 这条路是谁提出来的，试过哪些被否掉？
4. 「守卫」这一手（改内容漏字就 build 失败）是怎么想出来的？实际拦过几次？
5. 现在还有哪类字没进子集，用户会看到什么后果？
6. 这件事你愿意在下个项目上重做一遍吗，为什么？

备选（后续篇，素材同样在仓库内）：五级项目体系四门禁怎么用在自己身上；一台物理机搭内网闭环 P0–P6 验了什么；本站从 v4 做到双语上线的全过程。

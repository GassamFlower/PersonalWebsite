## 1. 两条边界（先划死，避免走回头路）

### 1.1 独立文章页：2026-10-17 用户批准放开（取代本批原定的「不做」）

原裁决（2026-10-16）：宪法 §1 是纯静态单页站，§1.1 只放开「两个静态 HTML = 一种内容的两种语言」，多页 = 修宪，故采用原生 `<details>` 就地展开，并写死触发条件「文章 ≥ 6 篇或 zh 初始 HTML > 200 kB 再议」。

**用户 2026-10-17 显式批准提前触发**：「将写作这里做成卡片形式，点击卡片进入新的页面，也就是当前专属文件页面」。已按修宪程序在宪法加 §1.2（允许构建期预渲染的静态子页），本区实现随之改版：

- 写作区渲染**卡片**，卡片整体是一个原生 `<a>`，指向 `/PersonalWebsite/writing/<slug>/`；英文页指向 `/PersonalWebsite/en/writing/<slug>/`。
- **`<details>` 就地展开装置撤下**（`expand`/`collapse` 两个字典键一并删）——同一篇文章不再有两处阅读面。
- 仍守的硬约束：无路由库、无客户端路由（子页由 `site-react/scripts/prerender.mjs` 逐个发射目录 `index.html`，路径在 `src/lib/routes.ts` 里按 `location.pathname` 解析）；每篇子页的正文**写进自己的初始 HTML**（§17，无 JS 也能读完全文）；双语仍是同一条 md 真源的两个静态副本，禁止平行事实源；子页 URL 用 ASCII `slug`。
- 分享定位：文章自带永久路径 `…/writing/<slug>/`，比旧方案的 `#writing-<n>` 锚点更适合外站引用（`docs/外站-X-内容日历.md` 直接用页链）。

**卡片与列表的取舍**：卡片是"一份内容一块"，不是新装置——它承载的仍是 `date + title + summary` 三个真源字段，不加图、不加标签、不加悬停动效堆料（§1.2 的反表功口径不变）。

### 1.2 不复活已被 v7 撤下的装置

`技术栈 rail`、`labelStack`、雷达图 / 能力图谱（CapabilityMap）均已整区下线，**本批不得以"加 skill"为由请回任何一种**。理由沿用 v7 的裁决：那些是自我表功式装饰，且用户明确反感。

能力档位的体裁（2026-10-17 用户裁决改版，**取代此前「台账条·一行一域」的定法**）：用户原话「会的东西这里没必要分类这么多域，控制下，改为整体，描述些更多细节」。7 行逐域台账撤下，改渲染**一整段自述（四小段）**，细节写在段落里；档位计数仍由真源算出不手写。真源落点：`src/content/capability.md` 一条记录，字段 `intro: [四段]` + `introEn: [四段]`（守卫新增一条：两侧条数必须相等，缺侧即 `exit 1`）；`src/content/skills/*.md` **七份全留**，继续充当明细真源与 `level` 计数源（页面不再逐域铺行，`note` 仍不上页——这是"整体化"的代价，将来若做技能子页面直接复用它）。段落按长文口径走系统 sans 并打 `data-font="sans"`（沿用 v8.0-b 的取字口径，长文不倍增字体字节）。

档位只有两档可用（`已交付` / `会用`）——**skills 真源里没有「在学」档，页面就不写「在学」**，代编即踩诚实红线。

## 2. 区序与编号（唯一推荐，不是选项菜单）

新区「能力档位」插在**案例 03 之后**，编号 04；后续全部顺延。2026-10-16 用户双语目测后裁决撤下「来路」编年区（罗列与故事区重复），编号再收一档；此后「附录 · 工作台之外」（2026-10-16）与「成长」月度索引（2026-10-17，见 §10）两区又先后撤下。当前区序：

```
封面 → 02 故事 → 03 案例 → 04 能力档位 → 05 写作 → 06 规矩 → 封底
```

为什么紧挨案例：案例回答「做成过什么」，档位回答「手上的工具到什么程度」，读者这两问是连着的；排进编年/月志一类罗列区之后，说服力就衰减（来路、成长两区即因此先后撤下）。

改动面（落码时逐条核对）：`App.tsx` 插组件；`SiteNav` 标签与编号；5 个组件里硬编码的 `plateRail` / `<span className="meta">0n</span>`；`i18n/ui.ts` zh+en 双份；`Contact`/`Hero` 三链目标不变。

## 3. md 契约（写作 v2）

```yaml
---
title: 中文衬线字体，我裁到 122 kB
date: "2026-10"
summary: 一句话摘要（列表行显示）
titleEn: "..."
summaryEn: "..."
---
正文用 markdown body（段落空行分隔）。
```

- **正文放 md body，不放 frontmatter**：`body` 已被 growth 集合占为字段名（`GrowthData.body`），复用键名会让 `hasAll` 判别与守卫语义打结。`getWriting()` 改为携带 `Entry.body`。
- 判别键是 `title+date+summary+slug`（`site-react/src/lib/content.ts getWriting()`），v8.5 起 slug 纳入判别键：缺它既不上卡片也不发射子页。
- `published: false` 可压稿（沿用 cases 的既有做法）。
- 正文内**禁止**：外链图片、真实公司/客户名、无法回原文核对的数字、代码仓库里不存在的路径。
- `source` / `sourceName`（可选，均 ASCII）：文章的外部出处。渲染在子页正文之后一条 `ink-link`，
  不进正文语法——`markdown.ts` 只认 `## ` / `- ` / 段落，`check-content` 规则④ 的 `INLINE` 明令禁止
  `[文本](链接)`，所以链接只能走真源字段这条路。标签「出处」/「Source」在 `i18n/ui.ts` 的 `post` 段。
- 正文红线补一条：不得出现编辑过程话术（「这篇文章以…为准」「写到这儿必须交代」「待你口述」）。
  裁决口径写在流程文档里，读者看到的只能是成稿。

## 4. 守卫（三处，缺一即视为未落地）

1. `scripts/check-content.mjs` 新规则④：writing 集合每篇须有 `titleEn` + `summaryEn` + `bodyEn`；**body 与 bodyEn 都非空**才允许入列表；缺键 `exit 1`（沿用 i18n 批 2–4 的纯拉丁串豁免）。
2. `node scripts/fonts.mjs`：文章正文必然带入千位新字 → 改完内容**必须**重跑再 build，否则 `--check` 报红（历史上「跳」「哪」「曾」三次实测拦停）。子集体积涨幅须记录在本文 §7。
3. 子页路径守卫（v8.5 改版）：`slug` 必填 + ASCII 格式 + ≤40 + 目录内唯一 + 不用保留段 `en`——四条都在 `check-content.mjs` 规则④。可访问性面：卡片与「回写作区」「中/EN」全是原生 `<a>`，键盘可达不靠 JS；`:focus-visible` 环由 global.css 统一给（砖红 2px + offset 3px）。

## 5. 机器可读层承接

`site-react/index.html` 的 JSON-LD `@graph` 已有 `Person` + `WebSite`（主页两张 + 子页四张都带这一段，站点级事实不逐页重写）。v8.5 补上每篇一个 `BlogPosting`：由 `site-react/scripts/prerender.mjs` 的 `blogPosting(page)` 在发射子页时注入该页 `</head>` 前，字段全部取本篇真源（`headline`/`description` = 标题与摘要的该语言副本、`datePublished` = `date`、`inLanguage` 按页语言、`author` 指 `#person`、`isPartOf` 指 `#website`、`mainEntityOfPage` = 本篇 canonical URL）。不含配图字段（站点级 og 图不属于某一篇，不虚报 `image`）。
**顺带修一处口径冲突**：批 4 写的 `knowsAbout` 是一份技术栈清单，而 v7 已把技术栈展示整面下线；改为按 skills 真源的**域 + 档位**语义（「数据采集与自动化」「运维与部署」等），不列具体框架名。

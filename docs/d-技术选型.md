> 状态：`[草稿]`，待用户确认

## 1. 产品形态（已确定）

- **形态**：单页长站（single-page）· **纯静态** · 无后端 / 无数据库 / 无登录 / 无后台。
- **内容性质**：以"内容展示 + 简单交互"为主——锚点导航、滚动动效、复制微信、成长记录定期更新。
- **维护者**：个人（会改 md）。

## 2. 唯一推荐技术栈

| 层 | 选择 | 理由（结合本项目） |
|---|---|---|
| **前端框架** | **Astro** | 纯静态零 JS 默认、构建后是干净 HTML/CSS、加载极快；**md 驱动内容**完美契合"成长记录月度一更 md"；组件化但轻量。 |
| **样式** | **原生 CSS + CSS 变量（token）** | 精致站以排版为主，无重型 UI 组件需求；用 CSS token 管理配色（骨白/近黑/深橄榄/铜棕），轻量高性能。 |
| **内容** | **Markdown（md/mdx）+ Frontmatter** | 成长记录、案例、能力条目用 md 或数据文件，构建时生成。 |
| **交互** | **CSS + 原生 JS（少量）** | 淡入动效用 IntersectionObserver + CSS；复制微信用 clipboard API + prompt 兜底。 |
| **部署** | **静态托管**（GitHub Pages / Vercel / CloudBase / EdgeOne 之一，上线门选） | Astro 构建后是纯静态，随处可部署；按用户既有偏好选。 |
| **字体** | 思源宋（标题衬线，可超粗字重 editorial）+ 思源黑（正文）；编号/日期用等宽（IBM Plex Mono 或系统等宽）| 契合建筑事务所/精品咨询的克制工程 + 档案卷宗感；中文 webfont 大则用 CDN 子集或系统字体回退。 |

> **核心理由**：本站是"内容排版的单页站"，Astro 的"静态优先 + 零 JS + md 驱动"是压倒性优势；无需 React/Vue 的重型生态与运行时开销。

## 3. 为什么不选其他方案（被淘汰方案 ≥3）

| 被淘汰方案 | 为什么不选 |
|---|---|
| **纯手写 HTML/CSS/JS** | 成长记录要手改 HTML，放弃 md 驱动的便捷；后期增改案例/记录容易出错、难维护；不符合"会改 md 就够"的维护能力。 |
| **Vite + React** | 本页面交互极简（锚点/复制/淡入），用 React 平白引入 JS 运行时 + 依赖 + 构建复杂度，**大材小用**；首屏 JS 和加载成本上升。 |
| **Next.js（SSR/SSG）** | 服务器渲染体系对纯静态单页站是**冗余**；Asstro 做静态内容站更轻、更快、更简单；个人站不需要 SSR 的动态特性。 |
| **CMS（如 Strapi/Sanity/WordPress）** | 引入数据库 + 后台 + 登录，完全违背"纯静态、无后台、会改 md"的轻量定位；维护成本高。 |
| **SSG 里的 Gatsby** | GraphQL 数据层对个人站过重，学习/维护成本高；Astro 更现代、更快、上手更简单。 |
| **Tailwind/重型 UI/动效框架** | 排版主导的克制编辑风，原生 CSS + token 足够；避免依赖层级和样式锁定风险。 |

## 4. 换栈触发条件（何时需要重新评估）

如果出现以下任一情况，需重新评估技术栈：
- **要加后台/登录/多页博客系统** → 介入 CMS 或 Vite+React（但从立项看短期内不会）。
- **成长记录要变成复杂文章系统**（分类/标签/搜索/评论）→ 可能换 Astro 多页面或接 CMS。
- **有在线下单/报价/JS 重型交互需求** → 若走到接单③档，需引入交易能力（仍建议第三方表单/服务，不轻易换框架）。
- **联合团队协作/需要复杂状态管理** → 才考虑 React 生态。

## 5. 选型小结

**唯一推荐：Astro + 原生 CSS（token）+ Markdown 驱动 + 静态托管。**
> 满足"会改 md 就能维护、生成快、无可视化后台、加载快、契合克制工程/档案卷宗的编辑审美"。纯静态优先，无后端负担。

## 5.5 WebGL / 3D 炫技增强（v4 · 2026-08 用户授权引入）

> 定位："炫技"不推翻栈，只补"记忆点"。全站仍为 Astro 静态站，仅在指定高光点做克制 3D 粒子，其余守 v4 冷档案克制。

- **新增依赖**：`three`（WebGL）作为唯一新增运行时库；**不引** GSAP/GreenSphere等动效全家桶（可缩放 ECMAScript 模块，仅打包使用处）。
- **落地**：Hero 单点克制的粒子/点阵 3D 场（墨蓝单色、低透明、随鼠标视差缓动）。可选扩展：深墨案例区数据点阵。
- **纪律（硬约束）**：
  - 3D 场景**永远做背景层**，前景文字保持高对比、可读。
  - 单色（墨蓝），不用彩虹/霓虹/荧光。
  - `@media (prefers-reduced-motion: reduce)`：**直接不初始化 WebGL，内容全量可见**（不秀 3D）。
  - **无 JS / WebGL 不可用**：div 兜底，纯文本渲染，布局不破。
  - AST 与性能：粒子数量在移动端降档、限制 `pixelRatio`，控制 DPR。
- **换栈触发**：若 3D 导致明显加载慢/机耗、或与上线转化冲突 → 只保留纯原生微炫（不 WebGL）。

## 6. 第三版技术栈（v3 · 2026-08 用户授权换栈 · 修订 §2 唯一推荐与 §3 淘汰）

> 用户已确认：把前端框架从 **Astro 换到 Vite + React**，3D 改用 **r3f**，样式继续用**经典 CSS（CSS Modules + 全局 token）**。§2-§3 的「选 Astro / 不选 Vite+React」在此为 v3 更新；内容/视觉/纯静态约束不变。

| 层 | 选择 | 说明 |
|---|---|---|
| 构建 | **Vite** | `vite build` → `dist/` 纯静态；dev HMR 更顺 |
| 框架 | **React 18** | 渲染层，承接 v4 视觉与 9 区 |
| 3D | **three + @react-three/fiber (r3f)** | 仅 Hero 高光点，克制 |
| 样式 | **经典 CSS + CSS Modules + 全局 token** | 不用 Tailwind / UI 框架 |
| 内容 | `src/content/**` md 构建时读入 | 不硬编码 |
| 部署 | 静态托管（GitHub Pages / Vercel）| 不变 |

**换栈的取舍（诚实）**：
- 换栈让 **React 生态与 r3f 组件化**成为可能（Hero 3D 声明式、易扩展）。
- 代价：`dist` 引入 React 运行时与依赖，首屏 JS 略增；页面需按 `v4` 保真重写。
- **不被「全家桶」**：不引 react-router（单页锚点）/ 全局状态库（不需要）/ 动效 GSAP 全家桶；其他都尽量用经典 CSS + 原生 JS。

**回退触发**：若 r3f 重写导致明显卡顿/包体积失控/移动端降级，或与上线转化冲突 → 保留 CLI 的纯 CSS/原生轻动效、不 hook 3D（仍合法，见后 §回退）。

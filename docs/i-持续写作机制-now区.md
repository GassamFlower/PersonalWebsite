## 2. 结构定案（推荐即写，供逐条裁决）

### D1 · now = 首屏下的「当下」区，**不是独立 `/now` 页**

- 真源：`src/content/now.md` 单条记录，frontmatter 含 `updated: 2026-10-15` + 若干字段（建议三档：在做 / 在学 / 在读或闲置项），英文按 h 文档 D2 用并列 `*En` 字段 + 覆盖率守卫。
- 展示：新增 `Now.tsx` 一个组件，插在 `Hero` 之后、`Story` 之前（`App.tsx:26` 位）；体裁沿用 v6 的细线 + 编号 + mono 眉栏，**不新增色相、不新增装置**（v6 克制条款）。
- **为什么不独立成页**：宪法 §1「单页站」的现行边界只允许同一事实的语言副本（§1.1），独立 `/now` 属新增内容页，**需要再一次宪法修订才能成立**。放首页一个区，是本机制的最小合规动作；且 now 本就该和履历同屏对照（"当下 vs 来路"），展示效果也更符合站体。
- **诚实条款**：区内明写 `更新于 2026-10` 这类时间戳，**不写"每月更新"承诺**——更新停了不留尴尬，时间戳自己会说话。在学就写 in progress，禁止 retroactively 把 now 旧条目改写成"早就完成"。

### D2 · growth 更新节奏 = 运维约定，不是 build 守卫

- 约定：每月第一个周末补写上月条目（纯流程承诺，写进本文档即可，不进站点文案）。
- 唯一可机检的点：`month` frontmatter 与文件名一致（防"旧条目冒充新条目"，诚实红线的结构性守卫）；落点见 §5 规格（新建 `scripts/check-content.mjs`，挂两条 build 线末尾，与 h 文档批 2 计划的覆盖率守卫同址同构）。
- **不做**"缺当月条目即 exit 1"式守卫——漏写是正常月，构建不该因此红。

### D3 · RSS/feed = **本轮不做**（判断，不是选项）

- 理由：feed 的价值在长文回访；68 字符/月的条目进 feed 是往聚合器里投噪音。
- 触发条件（写死在此，满足才重新立项）：growth 连续 3 个月出现 **≥500 字符长条目**，或 now 区机制跑稳半年后。届时用 `scripts/feed.mjs` build 期产出静态 `feed.xml`（只发布 growth，zh 先行），仍属纯静态、无违宪。

### D4 · 可读性 = 只约束"长文出现的地方"

- 18px 标准**不适用**于 v6 的图鉴标签/规格表体裁（那是眉栏不是正文）。
- 落地项一条：Now 区的多行文本字段加行宽上限（≤75 字符 ≈ `max-width: 40rem` 量级）；`--text-base` 是否升档，留待将来真出现长文条目时随 D3 一起议，**本轮不动全局令牌**。

## 5. 实施规格（架构门依据，落码前唯一真源）

### 5.1 内容真源：`src/content/now/current.md` 单条记录

- 放独立集合目录 `now/`，全站恒一条；更新 = 改写该文件并滚动 `updated`，**不开历史副本**（历史归 growth 管，职责不重叠）。
- frontmatter 规格（与 `src/content.config.ts` 现有集合同构，中文真值 + `*En` 并列，沿用 h 文档 D2）：

```yaml
updated: "2026-10"          # 唯一判别键之一；只到月，与诚实时间戳一致
doing:                      # 在做 1–3 条，字符串数组
  - text: …
    textEn: …
learning:                   # 在学（可空数组；有则必须真实，宪法 §7 三档同源）
  - text: …
    textEn: …
note: ""                    # 一行闲笔（可选，读/听/闲置项都归这里），noteEn 同理
```

- site-react 侧：`content.ts` 增加 `getNow()`——判别键 `updated` + `doing`，返回单条（多于一条即视为数据错误，交给守卫拦）。
- Astro 线**不跟进**（退出部署=历史线，h 文档批 1 已有同判例）；`src/content.config.ts` 加 `now` 集合声明仅作真源校验，避免 Astro 校验报孤儿目录。

### 5.2 UI 字典槽位（`site-react/src/i18n/ui.ts`）

- 键轨：`now.kicker`（眉栏「当下」）、`now.updated`（"更新于"前缀）、`now.doing` / `now.learning` / `now.note`（行标签）。
- en 侧措辞**按 h 文档 §3 流程：我起草对照 → 你逐条裁决**，不预制。

### 5.3 组件与版式（`Now.tsx`，插在 `App.tsx:26` Hero 之后）

- 体裁完全复用 v6 既有零件：细线分隔 + 等宽编号 + mono 眉栏 + 状态点（在学行沿用 skills 的"在学"显示档）。**不新增色相、不新增装置、不新增动效**——v6 克制条款原样适用，故 v6 文档无需增补。
- 行宽：`doing/learning/note` 多行文本容器 `max-width: 40rem`（≈75 字符），本区内部自定，不动全局 `--text-base`。
- 语言：随 locale 走字典 + `*En` 字段，无独立处理。

### 5.4 守卫：新建 `scripts/check-content.mjs`（build 末尾，两线挂钩）

1. growth：`month` frontmatter === 文件名 `YYYY-MM`；
2. now：`now/` 下恰好 1 个 md；`updated` 形如 `YYYY-MM`；数组条目非空串；
3. 预留挂点：h 文档批 2 的 `*En` 覆盖率守卫将来并入同脚本，不另立门户。**（2026-10-15 已并入：规则③ 上线，now 条目 `text` 含中文须有 `textEn`，反向实测删键即 exit 1）**
- 失败行为：exit 1 并列出条目（与 fonts `--check` 同构，该机制已被证明能当场抓错）。

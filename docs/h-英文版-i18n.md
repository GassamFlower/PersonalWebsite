# h · 英文版 i18n 方案（立项 + 架构门）

> 2026-10-14 用户「同时加一个英文版本的」，范围经确认 = **整站英文版，现在就做**。
> 本文是立项与结构定案；按门禁纪律，**未过确认不落码**。真源关系：视觉条款仍属 `docs/视觉方向-v6-技术图鉴.md`，本文只管"同一份事实的第二种语言"。

---

## 0. 一句话定性

英文版**不是中文站的翻译件，而是同一份事实的第二种语言版本**：事实一份，措辞两套。
这条决定了后面所有结构选择——凡可能让两种语言"讲出不同的事"的设计，一律不用。

## 1. 先量清工作量（实测脚本统计，不是估）

| 对象 | 实测 |
|---|---|
| 内容真源 | **31 个 md / 242 个字符串字段 / 4,777 字符**：cases 1,536（5 文件）· skills 1,513（7）· timeline 800（6）· growth 609（9）· offcat 319（4） |
| UI 串 | 两条线组件/布局里 **163 条去重中文串，共 1,457 字符**（区名、眉栏、表头、徽章、按钮、脚注轨）——这批当前**硬编码在组件里**，本身就是「内容真源」条款的既存偏离 |
| 枚举 | `status`（已上线/内部系统/开发中）、`level`（已交付/会用/在学）、附录四档（已验证/进行中/计划中/参考）的**中文字面值锁在 `src/content.config.ts` 的 schema 里** → 英文侧只做显示映射，不改数据本身 |

结论：真正需要人裁决的英文文字量 ≈ 4.8k + 1.5k 字符，量级可控；风险不在体量，在**措辞把事实说大**。

## 2. 结构定案（推荐即写，供逐条裁决）

### D1 · URL 与产物 = 两个静态 HTML：`/PersonalWebsite/`（zh，默认）与 `/PersonalWebsite/en/`

- **不用 SPA 内 JS 切换**：宪法 §17 / §31「无 JS 时关键内容仍完整可见」——若语言靠 React state，英文访客拿到的初始 HTML 是中文，等于英文页在无 JS 下不存在。
- **不用中英同屏并列**：v6 每个图版的排面是按中文行高与字宽算的（§3 规格表体裁），双语并列要么行高翻倍、要么砍内容，两者都比现状贵。
- **代价**（诚实列出）：`scripts/prerender.mjs` 要按 locale 循环产出两个 HTML；Astro 线加 `src/pages/en/index.astro`；`fonts.mjs --check` 的字符集要覆盖两语言渲染结果（它本来就会覆盖，因为读的是两条线的 dist）。
- **宪法 §1「纯静态单页站」需追加一句解释**：一份内容 · 两种语言 · 两个静态 HTML，仍**无后端/无路由库**（不引 react-router，切换器就是两个 `<a>`）。

### D2 · 内容真源 = 同一个 md 内并列字段（`title` + `titleEn`），**不开 `src/content/en/` 平行目录**

- 理由：平行目录允许"中文说 A、英文说 A+"而无人报错；并列字段让 `date`/`order`/`status`/`stack` **只有一份**，语言差异被限制在措辞层，这是把诚实红线做成结构约束。
- **覆盖率守卫**：`build` 末尾新增检查——凡有中文值而缺 `*En` 的字段即 exit 1 并列出条目（与刚上线的字体子集 `--check` 同构，那个守卫今天已当场抓到 2 次缺字，机制被证明有效）。

### D3 · UI 串 = 抽 `site-react/src/lib/i18n.ts`（zh/en 两份字典 + 枚举显示映射），Astro 线同构

- 这一步是**重构，不是新增**：抽出后中文站的可见文字必须逐字不变，用"渲染后文本 diff（zh 侧）"证明，不看代码看输出。
- 顺带处理既存偏离：联系方式（微信号与三个邮箱）现在硬编码在 `Contact.tsx/.astro`，属内容不属 UI，应挪进 `src/content/contact.md` 由两语言共读（同一份事实，不翻译）。

### D4 · 字体：英文复用现有衬线子集，**不引第二套西文字体**

- 拉丁 `A-Za-z0-9` 与常用标点已在 `scripts/fonts.mjs` 的 `MARGIN_CP` 余量内；英文正文若引入新符号，`--check` 会拦住并重跑（成本：一次生成，字重体积几乎不变）。
- 若想给英文站换 IBM Plex Serif 之类更讲究的西文显示字，那是 +1 子集文件、+1 视觉决策，**不在本轮**（v6 的克制条款：不新增装置、不新增色相，字体同理）。

### D5 · 分享卡片 = 两张：`og.png`（zh）/ `og-en.png`（en）

- `og:locale` 各自为本语言 + `og:locale:alternate` 互指；`og:url` 指向各自的绝对 URL。
- 仍由 `scripts/og_image.py` 参数化 locale 绘制（**不用 AI 生图**：假汉字那条红线同样适用于假英文）。

### D6 · 语言切换器 = 导航右端 `中 / EN` 两个链接

- mono 12px，当前语言**墨实底**、另一种**墨描边**——沿用 CapabilityMap 已定的墨色二档纪律，**不新增色相、不新增装置、不加下拉**。
- 位置在 SiteNav 索引之后，窄口（<640px）收到导航末位；两个链接是原生 `<a>`，无 JS 可用（符合 §31）。

## 3. 英文由谁写（红线，不是流程洁癖）

- 我起草对照表（**原文 → 英文 → 为什么这么译**），你逐条确认后我才写进 `src/content/`。
- 禁止：英文里出现中文真源没有的事实；把「参与 / 支持 / 维护」译成 `built / led / architected`；把诚实三档译大（升档）。
- 术语表先定，避免同一事实两种说法：

| 中文 | 英文 | 取舍 |
|---|---|---|
| 已上线 | Live | 不用 Deployed/In production（暗示规模与运维职责） |
| 内部系统 | Internal | 不写成 Enterprise |
| 开发中 | In progress | 不用 Beta / Production-ready |
| 已交付 | Delivered | 技能档最高档，只给真交付过的 |
| 会用 | Working knowledge | **不用 Proficient**（Proficient 是"精通"侧） |
| 在学 | Learning | |
| 已验证 / 进行中 / 计划中 / 参考 | Verified / In progress / Planned / Reference | 附录四档 |
| 署名「一个故事」 | 建议**不译**，保留中文原样 | 它是代号不是名词；若要英文版署名再单列一条决策 |

## 4. 分批过门（每批 build 全绿 + 你能目测，不一次摊开）

| 批 | 内容 | 过门判据 |
|---|---|---|
| 1 | i18n 字典抽取（163 条 UI 串）+ locale 进 SSR/prerender，先产出 `/en/` 骨架（英文字段缺失时按守卫报错，不静默回退中文） | 中文站渲染文本逐字不变；两线 build 绿 |
| 2 | schema 加 `*En` 可选字段 + 覆盖率守卫 + **1 条样板**（建议 `cases` 里 order 最小的工程用车助手，它是外单可公开叙述） | 你裁决这一条的英文措辞，作为全站口径基线 |
| 3 | 全量对照表：31 个 md / 242 字段，按集合分 5 张表一次交你审 | 逐条「照此执行 / 改」的裁决记录进本文档 |
| 4 | 英文 OG 卡、`中/EN` 切换器、`hreflang`、`<html lang="en">`、字体守卫重跑、全站 AA 与横向溢出复扫 | 你浏览器目测两个语言版本 → 上线门 |

## 5. 与当前收尾线的冲突（必须先说清的代价）

v6 中文站现在停在「你目测 9 区 → push」。加英文版会把它变成两件事：

- **方案 A（推荐）**：先目测并 push 中文站，英文版按 §4 分批跟进；`/en/` 上线时不改中文页一个字。代价：线上会有一小段时间只有中文。
- **方案 B**：等英文一起 push。代价：目测范围从 9 区变 18 区，且批 3 的 242 条措辞要你逐条裁决 → 上线日推后数天。

批 1 是纯结构重构、不改观感，**可与你的目测并行**；批 2 之后才真正动到你眼睛看到的文字。

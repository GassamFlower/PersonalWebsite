## 1. 立项说明（项目是什么 / 面向谁 / 解决什么问题）

### 项目是什么
一个以「接单 · 交付凭证」为核心的单页长站，展示一位**能从零把内部数字化搭起来**的交付者形象。它不是普通简历，而是一份「把事做靠谱」的可信证明。

### 面向谁（三类受众）
| 受众 | 他们想看 | 站要给他们的信号 |
|---|---|---|
| 商务老板 / 有需求方 | 这人能不能托付项目 | 真实交付证据、敢托付、联系方式直接 |
| 技术大佬 / 合作方 | 这人有没有章法、值不值得合作/指点 | 体系区分、做事的规矩、方法论 |
| 小白 / 同行 | 找真实的学习对象、交流 | 边界诚实、公开成长、靠谱印象 |

### 解决什么问题
- **对访客**：30 秒判断「这个人可信、有边界、能独立交付、敢托付」，并在想合作时能低成本联系上。
- **对站主**：解决「空有本事、缺一个可信的接单/合作入口」的问题；把散落经历（法院8年/OPS/UUC/外卖/方法论）收束成一份可核实的交付凭证。

### 核心价值主张（一句话）
> 「把一团乱麻，理成能用的系统」——遇到数字化空白，敢接、也能接。

## 2. 功能边界（第一版做什么、不做什么）

### 第一版做（MVP · 9 个分区结构完整）
1. 首屏定位（大字定位句 + 名字小字 + 目录入口）
2. 品牌故事（克制 2-3 句身世转折）
3. 四梯队能力地图（独立交付 / 业务落地 / 工具提效 / 边界诚实）
4. 做过的事（垂直时间线 5 节点）
5. 项目案例（4 案例 · 脱敏截图/示意 + 问题→我做了什么→技术栈→证据）
6. 成长记录（月度条目 · md 驱动）
7. 做事的规矩（四门禁 · 体系化）
8. 联系交流（微信 + 邮箱 · 加微信按钮）
9. 底部（诚实边界 + 匿名声明小字）

### 第一版不做（明确划界）
- ❌ 不做在线报价 / 自助下单 / 服务清单页（接单**③档**——易夸大能力，违背诚实底线）
- ❌ 不做博客系统/文章详情页（成长记录用单页条目即可）
- ❌ 不做登录/会员/后台管理（纯静态站）
- ❌ 不做婚庆/数据标注相关未定内容
- ❌ 不放真人头像/真实公司 logo（匿名化）
- ❌ 不放简历里无法核实的 AI 项目/夸大表述

## 3. 用户路径（产品流程）

**单页站，访客从上往下走，随时随地可跳转联系：**

```
进入首屏（30秒立信任）
   ↓
品牌故事（2-3句身世，增信）
   ↓
四梯队能力地图（分层坐实"能独立交付什么、懂什么、会什么工具、什么不装"）
   ↓
做过的事（时间线，验证交付历史）
   ↓
项目案例（脱敏证据，证明能独立搭建）
   ↓
成长记录（显示自驱与长期主义）
   ↓
做事的规矩（体系化，令人放心）
   ↓
联系交流（加微信 / 邮箱）←——— 任何分区导航/CTA 都可到这里
```

**三条转化路径：**
- 首屏CTA「看看我能做什么」→ 滚动到能力/案例
- 首屏CTA「联系我」→ 直接到联系区
- 导航锚点随时切换分区 + 每区可跳「联系」

**核心成功动作**：访客看完 → 加微信（G10S7H21）→ 聊需求。

## 5. 技术路线初步判断

- **形态**：单页长站 · 纯静态（无后端、无数据库、无登录）。
- **前端**：Astro（推荐，纯静态零 JS 默认，md 可驱动成长记录）。
- **样式**：CSS（原生 / 少量组件封装），无需重型 UI 框架。
- **数据**：内容几乎全静态；成长记录/案例用 md 或数据文件在构建时生成。
- **部署**：静态托管（GitHub Pages / Vercel / CloudBase / EdgeOne 之一，待选型步骤定）。
- **素材**：唯一素材 = 骨白纸/石质噪点（可省）+ 各案例脱敏示意槽/截图；文字/分隔线/时间线/卷宗编号等代码原生。

> 详细唯一推荐、淘汰方案、重评估条件 → 见 `docs/d-技术选型.md`（阶段 2）。

## 6. 爆点差异（差异化亮点）

1. **敢亮能力边界**：四梯队「独立交付 / 业务落地 / 工具提效 / 边界诚实」——恰恰是"不装"建立最大信任，且用层次证明"能交付"。
2. **有真实交付凭证**：OPS / UUC / 工程用车助手都是真实从零搭起并交付/上线的产品，非简历套话。
3. **有体系、有规矩**：展示「做事的规矩」（四门禁 + SSOT 纪律），让技术方一眼看出"有章法"。
4. **匿名但可信**：隐去公司名/logo，反显专业操守，且规避合规风险。
5. **[草稿] 定位差异**：「把一团乱麻，理成能用的系统」——直面客户最怕的"只会套模板"，用真实项目背书。

## 9. 第二版边界与扩展决议（2026-08 立项 · 待用户最终确认）

> 第二版承接 V1（纯静态单页站）核心不变；本章为新增，与 V1 各节冲突处以后者为准。

### 9.1 售后与客服（新增）
| 项 | 决议 |
|---|---|
| 留言落地 | **第三方静态表单服务**（Formspree / Getform 类）→ 单向出站直发站主邮箱；本站保持无后端 / 无数据库 / 无登录 |
| 后台管理 | **不建自建后台**；客户跟进用外部台账（飞书表格 / 云表格等，不在站内） |
| 客服微信 | 现号 G10S7H21；悬浮入口 + 二维码；区分「售前咨询 / 售后支持」话术 |
| 响应承诺 | 站上明示「留言 1 个工作日内回复」，承诺并兑现 |
| 敏感信息 | 姓名 / 手机 / 微信仅存第三方与站主邮箱，不入站内存储（守匿名化红线） |

### 9.2 扩展方向（优先序）
1. **合作流程透明化**：「怎么询价 → 怎么开工 → 怎么验收 → 交付后怎么售后」四步，并入『做事的规矩』区。
2. **项目过程透明展示**：案例深化为「问题 → 我做了什么 → 证据 → 过程留痕」，强化交付凭证（不造假过程）。
3. **成长内容资产化**：成长记录升级为带钩子的方法论短文，仍 md 驱动、不单独开博客。
4. **客户见证 / 脱敏反馈**（依赖材料 `[来源待补]`）：脱敏实名（不点名）甲方案持反馈，严格过脱敏检查后入站；材料不到位则不开。

### 9.3 动效
引入**克制滚动动效**（吸顶导航 / 滚动渐进显现 / 微交互）；用原生 / 轻量 JS，尊重 `prefers-reduced-motion`，无 JS 时关键内容全显；保持单页长站。

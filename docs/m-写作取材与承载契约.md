## 0. 先划两条死线（不划清后面每一步都会踩）

### 0.1 `Vibe_Coding/sources/article.md` 不是用户的文章

实测该文头 13 行：标题《驾驭AI Coding：一份面向团队的Harness Engineering落地规范》，**作者/公众号：腾讯技术工程，作者 atreusliu，2026-07-17，原文链接 `mp.weixin.qq.com/s/g4nTfxm7ebzRwkAVIGdIbg`**。全文用「我们」，通篇是 CodeBuddy / 工蜂 / iWiki / Knot / TAPD 等**雇主内部系统**，还带一个 `GONGFENG_ACCESS_TOKEN` 配置样例。

结论：**它不能改写成公众号体发到本站**——那是转载他人受版权保护的内容，仓库的 Apache-2.0 不覆盖第三方文章。要提它只有一种合法形态：作为「我读过的一篇」的**外部引用**（标题 + 作者 + 一句我自己的看法），且引用必须落在用户自己的判断上，不复述其正文。

### 0.2 真素材里没有「我」这一层

`skills/`（12 条）、`docs/`（4 本手册）、`templates/`（4 张门禁卡）几乎全是**给 AI 的规矩**——祈使句、清单、判定条件，没有场景；`sources/_archive/`（19 篇）看着像亲历记录，实为**保存下来的 AI 回答**（例：`前端-小程序遇到过问题的.md` 结尾是「要我直接动手改吗？」）。

公众号体的骨架是 **场景 → 冲突 → 转折 → 结论**，这套素材只给得出「结论」和一部分「冲突」。缺的那一层**只能用户口述**，AI 补即代笔（`docs/j` §1 红线），且懂行的人在 X 上一眼能看出没有现场感的方法论文章是空的。

**所以本批的落地节奏改定**：AI 出结构与双语 → 每篇向用户提 2–3 个**一句话就能答**的现场问题 → 用户答 → 定稿落盘。问题清单见 §2。

## 4. 先决工程：字体子集精确化 —— **已落地（2026-10-16），本节由「待办」改为「机制说明」**

原问题（实测）：`scripts/fonts.mjs` 的 `renderedChars()` 把 `src/content/**/*.md` **整份**读进子集输入，不看该字段实际用不用衬线渲染。三口径实测唯一码位：astro 页 606 / react 中文页 761 / react 英文页 87（此前**英文页根本没入扫**）/ md 全文 807，并集 905 —— 其中 **65 码位不出现在任何已发布 HTML**（`published: false` 压稿与不渲染字段照算）。素材侧同法实测：`skills/` 798、`docs/` 953、`sources/article.md` 864，一篇 2500–4000 字长文若照旧口径落盘约新增 **800–1200** 码位 → **首页多下 400~500 kB 字体**，等于全站字体总量翻倍。这就是「不做这一步就不上长文」的硬阈值。

已落地的两条改法（详见 `docs/视觉方向-v6-技术图鉴.md` §18）：

1. **取字口径改为渲染面**：不再扫 md 全文，递归扫 `dist/**/*.html` + `site-react/dist/**/*.html`。双语页与**未来的文章子页自动在面内**；`--check` 的缺字判定与真实渲染一一对应（顺序保证：`vite build → prerender → fonts --check`）。
2. **长文正文走系统 sans**：`Writing.module.css` 的 `.body p`/`.body li` 摘掉衬线，`Writing.tsx` 给这些元素打 `data-font="sans"`，`fonts.mjs` 的 `serifText()` 用标签栈把整棵子树挡在子集外。`--font-sans` 里的 Noto Sans SC **未自托管**，故长文落系统字 = webfont 零字节；标题 `.title`、段内小标题 `.h`、空态 `.empty` 仍衬线，维持本站「标题衬线 / 正文 sans」的体裁。

实测结果：子集 1080（HEAD）→ **978 码位**，三档 woff2 合计 499.9 KiB → **446.6 KiB（−10.7%）**，`[fonts] 覆盖率校验通过（子集 978 / 当前渲染 978）`，build 全链路绿。回归护栏随之改写：**长文上线后子集码位不应因正文长度而增长**（这是本批唯一的可证伪预测）。

⚠ **本批只入机制，字体产物不入**：那三个 woff2 是按当前工作区内容（含同工作区另一路会话未提交的 content 改动）重跑的，写进不含这些内容的 commit 会让 HEAD 自身「子集 ⊉ 渲染面」而红；HEAD 现存的 1080 码位档是新口径渲染面的超集，单独 checkout 仍过 `--check`。产物随下一次内容批重跑入仓。**因此 §5 的门禁顺序里「字体重跑」这一步尚未结算。**

⚠ 耦合约束：某元素若改回衬线渲染，必须同时删掉它的 `data-font="sans"` 标记，否则子集不含这些字，线上缺字回退。
